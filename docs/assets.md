# 美术与声音

Cataland 的视觉围绕海岸、自然地形和桌游聚落展开。森林、丘陵、牧场、农田、山脉与沙漠形成岛屿，建筑和道路使用明确的玩家色，纸色面板承载手牌和操作。声音由轻量的主题音乐、海岸环境与短促的游戏反馈组成。

地形、卡牌和应用图标由 Python 程序绘制，音乐与环境声由程序合成。生成脚本就是可编辑的资源源文件，图集、音频与平台图标作为成品随仓库保存。棋盘上的建筑、骑士、港口、强盗和商人则由 PixiJS 绘制。

## 视觉层次

地形提供环境与资源类别，数字牌提供生产信息，建筑与道路提供玩家归属，位置高亮表达正在进行的操作。这几部分分别绘制，使数字交换、强盗移动和玩家建设都可以独立改变。

地形采用柔和的绿色、土色、麦色和灰色，纹理与小物件表达森林、麦田、牧场和岩层。数字牌使用浅奶油色圆盘，6 与 8 的数字颜色更加醒目，圆点数量同时表示产出机会。

道路与屋顶采用玩家色，浅色轮廓使它们能从不同地形中识别。城市比村庄多一座塔楼，城墙围绕建筑底部，大都会在屋顶上方增加冠饰。骑士的等级用标记表示，激活状态通过直立与倾斜姿态表达。

普通界面图标来自 Lucide，资源和卡牌使用游戏自己的插画。文字、按钮与状态提示提供与图形相对应的含义。

## 地形图集

每块地形使用 512 × 512 的透明画布。六类地形横向排列，三种变化纵向排列，合成 3072 × 1536 的 WebP。图集帧名为 `forest-0`、`forest-1`、`forest-2` 等，其他类别是 `hills`、`pasture`、`fields`、`mountains` 和 `desert`。

图集中每帧的坐标、尺寸、源尺寸与透明区域由 `terrain.json` 描述。`meta.image` 指向同目录下的 `terrain.webp`，符合 PixiJS Spritesheet 的输入形式。

绘制使用位于 `(256, 278)` 的地表中心和 224 的基础半径，底部留有厚度与投影。场景据此使用横向中心、纵向 `278 / 512` 的锚点，并把图像缩放到地图的逻辑尺寸。改变地块轮廓或留白时，锚点与比例也需要一起理解。

场景根据地块类型与 `id % 3` 选择变化图。地形图像只表达环境，数字、名称、港口、道路和建筑由其他图层提供。发明卡交换数字时使用数字图层，地形插画继续位于原处。

## 资源与卡牌插画

插画的单格成品尺寸为 256 × 224，先以三倍尺寸绘制，再缩小形成边缘。图集采用八列，共 37 格有效插画，成品为 2048 × 1120。

八种资源与商品使用 `wood`、`brick`、`wool`、`grain`、`ore`、`cloth`、`coin`、`paper`。发展卡和进步卡使用序列化卡牌名，例如 `knight`、`victoryPoint`、`roadBuilding`、`commercialHarbor`、`alchemy`。两类牌中的修路共用 `roadBuilding` 插画。

`src/art.json` 保存每个名称的矩形位置及整张图集的宽高。`Art` 组件使用这些信息设置背景位置与比例，因此面板可以按不同尺寸显示同一幅插画。

插画与牌面布局分别负责内容和信息。插画表达卡牌主题，React 牌面负责名称、数量、所属路线、效果和可用状态。新增卡牌时，图集键、卡牌类型和页面引用需要对应。

## 应用图标

图标以一组相连的岛屿拼块、聚落、树林、麦田、矿石和港口组成。生成脚本以更高尺寸绘制，输出 1024 × 1024 的 PNG。

Tauri 桌面配置同时引用 PNG、ICNS 和 ICO。图标源图更新后，通过 Tauri 图标工具生成平台文件：

```sh
uv run scripts/art.py
pnpm tauri icon src-tauri/icons/icon.png
```

图标输出目录是 `src-tauri/icons`，实际打包使用的文件由 `tauri.conf.json` 的 `bundle.icon` 指定。首页主视觉也导入这张 PNG，因此图标更新会同时改变首页的岛屿图像。

## 生成图像资源

脚本使用内联依赖声明，Pillow 负责图像绘制与编码。可以分别执行需要修改的资源生成器：

```sh
uv run scripts/terrain.py
uv run scripts/illustrations.py
```

地形生成器同时写出 WebP 和 PixiJS 图集描述，卡牌生成器同时写出 WebP 和前端矩形索引。成品与元数据是一组资源，需要一起更新。

生成参数、配色、物体构造和随机变化都保存在脚本内。调整地形细节可以从对应类别的绘制逻辑入手，调整资源物件或卡牌主题则从插画生成器入手。

构建时，Vite 将 `public` 中的资源放到前端成品目录。运行时地形图集经 `new URL("/art/terrain.json", document.baseURI).href` 加载，关联贴图根据图集地址解析。

## 动画设计与实现

游戏中的变化分为棋盘导航、棋子状态和面板反馈三个部分。

| 变化 | 表现 | 实现 |
| --- | --- | --- |
| 缩放、归位 | 整张棋盘平滑变换，缩放围绕指针或视区中心 | `camera.ts` |
| 拖动 | 棋盘直接跟随指针 | `camera.ts` |
| 道路、村庄、城市、城墙、大都会出现 | 短暂的位移、缩放和淡入 | `scene.ts` |
| 骑士、商人、强盗移动 | 从原位置移至新位置 | `scene.ts` |
| 生产与支出 | 资源图标在棋盘与手牌之间移动，数字区域反馈变化 | `motion.ts` |
| 掷骰与获得卡牌 | 骰子旋转落定，卡牌进入手牌区域 | `motion.ts` |
| 野蛮人推进和来袭 | 船只沿航程移动，来袭后回到起点 | `motion.ts` |
| 分数与胜利 | 玩家栏反馈变化，出现胜利面板 | `motion.ts` |

棋盘在固定坐标中绘制，导航使用整个表面的 DOM 变换。棋子动画提取当前图像到透明覆盖层，由浏览器播放，结束后展示画布上的最终棋子。

规则状态决定结果，事件提供发生了什么和移动起点。动画表现这些结果，游戏不会依赖动画播放完成才能保存一个动作。新的状态到达时，已有动画可以结束并呈现新的局面。

动画强度为 0、0.5、1，分别对应关闭、轻柔和标准。设置会影响过渡时间、位移与缩放幅度。资源、分数和卡牌动画使用实际前后差异，首次进入棋盘则建立当前状态的显示基线。

## 音乐与环境

音乐源文件 `islands.wav` 是 48 秒的立体声循环，采样率 24 kHz，16 位 PCM。合成由和弦、分解音型和旋律组成，音色使用谐波、衰减包络和延迟叠加。

环境源文件 `shore.wav` 是 24 秒的立体声循环，使用经过频谱处理的噪声、周期性起伏与少量鸟鸣音型表达海岸。其采样率和位深与音乐相同。

生成方式：

```sh
uv run scripts/audio.py
```

脚本通过内联依赖声明使用 NumPy。`public/audio` 中的成品随桌面前端一起分发，运行时通过 Web Audio 解码并循环播放。

## 游戏音效

游戏音效由 Web Audio 振荡器、噪声、滤波器和音量包络实时合成。声音按事件种类组织。

| 事件 | 声音方向 |
| --- | --- |
| 点击 | 很短的音调反馈 |
| 掷骰 | 逐渐拉开间隔的短促碰撞 |
| 道路、建筑、城墙 | 低短音与轻微噪声叠加，表达落下 |
| 骑士 | 两个较高音调构成金属感 |
| 强盗、城市损失、野蛮人 | 低频下降与较暗的噪声 |
| 卡牌 | 轻短的高频翻动声 |
| 生产、交易、商人 | 两个依次上行的音调 |
| 奖励、防守成功、胜利 | 上行和声音列 |

音乐、环境和效果各有独立音量通道，再汇入主音量。首次鼠标或键盘操作时创建音频上下文，暂停的上下文在交互时恢复。调整音量使用短时间平滑变化。

事件游标只选择新事件，同一批更新中的相同事件种类合并播放。进入已有房间或打开对局记录时，以其历史末尾作为声音基线。

## 扩展资源时的关联

新增一种地形时，需要同时考虑规则中的资源产出、地图组成、图集帧、场景类别和翻译名称。新增卡牌时需要对应卡牌目录、效果、插画键与中英文描述。新增事件时则由事件种类连接记录、动画和声音。

共享资源通过图集和组件供多个界面使用。变更一幅资源插画可以同时作用于手牌、费用与飞行动画；变更一个玩家色可以同时作用于玩家栏、建筑、道路和骑士。这个组织方式使新玩法能够沿用同一套视觉与声音结构。
